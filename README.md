# Flow Bot / ФотоЖаб

Python-приложение для генерации и редактирования изображений и видео через
Google Labs Flow. Основной интерфейс — Telegram-бот; также есть канал MAX,
веб-приложение и отдельный режим для продавцов маркетплейсов.

Playwright поддерживает авторизованную Chrome-сессию, а `aiohttp` отправляет
запросы генерации. Это интеграция с веб-интерфейсом Flow: изменения на стороне
Google могут потребовать обновления клиента. Google-аккаунты, доступ к моделям,
квоты и ключи пользователь настраивает самостоятельно.

## Возможности

- Генерация картинок по тексту и фото, редактирование, вариации и апскейл.
- Видео по тексту, стартовому/конечному кадру и изображениям-референсам.
- Сценарии для карточек товаров, инфографики и рекламных материалов.
- Пул Google-аккаунтов, маршрутизация, контроль доступности и очередей.
- Кредиты, Telegram Stars, опциональная Robokassa, рефералы и атрибуция рекламы.
- Метрики в SQLite, административные команды и веб-панель.

Доступные модели и цены задаются в коде и конфигурации; часть ключей моделей
получена по аналогии и требует проверки на конкретном аккаунте.

## Требования

- Python 3.11 и Git.
- Google Chrome: приложение использует Playwright с `channel="chrome"`.
- Telegram-токен от BotFather и числовой Telegram ID владельца.
- Собственный Google-аккаунт с доступом к Flow и отдельный авторизованный
  Chrome-профиль. Обычный личный профиль браузера использовать не следует.

Зависимости находятся в [requirements.txt](requirements.txt). Команды ниже
соответствуют точкам входа исходного кода и CI; чистая установка не означает
автоматическую настройку Google-сессии или платёжных кабинетов.

## Установка

```bash
git clone https://github.com/molodayamama/flow-bot-public.git
cd flow-bot-public
python -m venv .venv
```

Активируйте окружение:

```powershell
# Windows PowerShell
.\.venv\Scripts\Activate.ps1
Copy-Item .env.example .env
```

```bash
# Linux / macOS
source .venv/bin/activate
cp .env.example .env
```

Установите зависимости и Chrome, если он ещё не установлен:

```bash
python -m pip install -r requirements.txt
python -m playwright install chrome
```

## Конфигурация и первый запуск

Заполните локальный `.env`. Значения ниже — только примеры:

```dotenv
TELEGRAM_TOKEN=123456789:replace_me
OWNER_ID=123456789
BOT_USERNAME=your_bot_username
USER_DATA_DIR=./google_profile
FLOW_BROWSER_API_KEY=replace_with_your_browser_client_key
CAPTCHA_PROVIDER=browser
CREDITS_SQLITE=1
ROBOKASSA_ENABLED=0
MAX_ENABLED=0
WEB_APP_ENABLED=0
```

`FLOW_BROWSER_API_KEY` требуется проверке конфигурации consumer-процесса;
его runtime-значение хранится только локально. Подготовьте отдельный профиль
Chrome и вручную войдите в свой Google-аккаунт с доступом к Flow.
Закройте браузер, использующий этот профиль, перед запуском бота.
Вспомогательный `login.py` **удаляет и пересоздаёт `google_profile/`**:
не запускайте его поверх настроенного профиля.

Из корня проекта запустите:

```bash
python flow_bot.py
```

Откройте своего бота в Telegram и отправьте `/start`. Для завершения процесса
используйте Ctrl+C. Запуск подключается к внешним сервисам; генерация расходует
квоты/кредиты Google, а платные captcha-провайдеры — баланс соответствующего
сервиса. Ключи captcha оставьте пустыми, если fallback не нужен.

Подробности: [настройка окружения](docs/ENV_SETUP.md),
[подготовка аккаунтов](docs/ACCOUNT_ONBOARDING.md).

## Дополнительные режимы

**Несколько Google-аккаунтов.** У каждого должен быть свой авторизованный профиль:

```dotenv
FLOW_ACCOUNTS=main=./google_profile;acc2=./google_profile_acc2
```

**Платежи.** Telegram Stars встроены в бота. Robokassa включается отдельно:
нужны собственный магазин, пароли, HTTPS-адрес и настроенные callbacks.
Начинайте с тестового режима и тестовых паролей. Настройки и маршрутизация
описаны в [ENV_SETUP.md](docs/ENV_SETUP.md).

**MAX.** Опционально включается через `MAX_ENABLED=1`, собственный `MAX_BOT_TOKEN`
и настройки polling/webhook. См. [CHANNEL_PARITY.md](docs/CHANNEL_PARITY.md)
и [MAX_SMOKE.md](docs/MAX_SMOKE.md).

**Веб-приложение.** Статика находится в `deploy/photozhab/`, API — в
`channels/web/app.py`. Для включения нужны `WEB_APP_ENABLED=1`, случайный
`WEB_SESSION_SECRET`, собственный `WEB_PUBLIC_ORIGIN` и HTTPS/reverse proxy.
Админку и внутренний API необходимо закрыть от публичного доступа.

**Seller-режим.** Отдельный процесс с `BOT_MODE=seller`, собственным Telegram
токеном и конфигурацией кошелька. Шаблон — `deploy/examples/seller.env.example`.
Общий backend включается через `INTERNAL_API_TOKEN` в обоих процессах.

## Структура

| Путь | Назначение |
| --- | --- |
| `flow_bot.py` | Сборка приложения и запуск |
| `config/` | Настройки окружения и моделей |
| `flow_provider/` | Chrome-сессия и HTTP-клиент Google Flow |
| `generation/`, `product/` | Генерация и пользовательские сценарии |
| `channels/telegram/`, `channels/max/`, `channels/web/` | Интерфейсы каналов |
| `accounts/` | Пул аккаунтов, здоровье и маршрутизация |
| `billing/`, `referrals/` | Кредиты, платежи и рефералы |
| `flow_core.py`, `metrics.py`, `storage/` | Общая логика и локальное хранение |
| `deploy/`, `deploy.sh` | Статика, примеры systemd/nginx, сценарий развёртывания |
| `tests/`, `tools/` | Тесты, диагностика и эксплуатационные инструменты |

## Проверки

Без запуска бота, реальных платежей и генерации:

```bash
python tools/check_tracked_secrets.py
python -m unittest discover -s tests -p "test_*.py"
python -m py_compile flow_bot.py flow_core.py flow_copy.py
```

Подробная матрица проверок — [VALIDATION.md](VALIDATION.md). Скрипты `live_*`,
захваты браузера, `test_tokens.py` и `test_recaptcha_params.py` не относятся
к офлайн-тестам и могут обращаться к внешним сервисам.

## Развёртывание и данные

Сначала адаптируйте примеры в `deploy/systemd/`, `deploy/nginx/` и `deploy/bin/`
под своего пользователя, каталоги и домены. `deploy.sh` — эксплуатационный
сценарий проекта, а не универсальный установщик: проверьте его настройки до
запуска. Браузеру на headless-сервере может потребоваться виртуальный дисплей.

Состояние хранится локально: SQLite, JSON, профили Chrome и временные медиа.
Перед обновлением делайте проверенную резервную копию runtime-файлов,
развёртывайте фиксированный SHA и сохраняйте совместимый путь отката.

Не коммитьте `.env*` (кроме шаблонов), токены, пароли Robokassa, Google cookies,
аккаунты Gmail, профили Chrome, HAR, базы, логи и дампы запросов. `.gitignore`
и аудит в CI помогают предотвратить повторную утечку, но не заменяют проверку
перед коммитом. Секреты, когда-либо попавшие в Git, нужно отозвать/заменить.

Публичные HTML-страницы содержат примеры контактов и реквизитов. Перед
развёртыванием замените их собственными проверенными данными; не используйте
эти страницы как готовые юридические документы.
